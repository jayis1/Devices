# Architecture and safety

Entry contact and staff check button plus an independent approach distance sample report by BLE to the hub. The hub owns the latest observation cache and derives UNKNOWN/CHECK_REQUIRED/OPERATOR_CHECKED; monotonic receipt age is required in a real implementation (prototype API currently omits expiry). Never present OPERATOR_CHECKED as compliance or proof of access: it is only a captured staff check plus sensor sample. Staff inspection remains authoritative. Network/cloud outages leave local checks possible; missing data must fail to UNKNOWN. Prototype currently has no BLE implementation, storage durability, TLS, user authentication, or MQTT. Keep API bound to loopback. No visitor identifiers or raw media are collected. Threats include radio spoof/replay, tampering, misalignment, stale data, and unauthorized API access; authenticated provisioning, BLE security, signed updates, authorization and rate limits are deployment blockers.
