# Architecture and failure behavior
The three ESP32-C3 nodes submit explicit user actions by BLE to the Raspberry Pi hub. The hub validates bounded frames, assigns receipt timestamps, deduplicates event IDs, and stores data locally. The phone is optional; no cloud is required for local checklists. On node loss, show last-seen time and retain prior state as stale, never silently mark an inspection complete. On hub restart, replay persisted event IDs idempotently. Cloud outage queues opt-in sync locally; no remote action is queued. On missing expiry date, label the record unknown and ask for manual review. A checklist is not a substitute for official emergency planning or inspection of supplies.

Security boundary: starter enrollment is not secure provisioning. Production deployment needs authenticated BLE enrollment, per-node credentials, revocation, encrypted local storage, user authorization, TLS, broker ACLs, signed updates, and threat review. The prototype must not be internet-exposed.
